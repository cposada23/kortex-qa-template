# {{TEAM_NAME}} — internal processes

> How THIS team actually works, one file per process, captured as you
> learn it (week-one feeds this; retros refine it). Sprint mechanics
> live in [workflow.md](../workflow.md) and [ceremonies-info.md](../ceremonies-info.md)
> — this folder is for everything else.

Suggested files — create them when you learn the real process, not
before:

- `bug-triage.md` — how bugs get prioritized, who decides, SLAs.
- `peer-review.md` — how test cases / PRs get reviewed here.
- `flaky-tests.md` — what the team does with flaky automation.
- `release-process.md` — how a release ships; QA's sign-off role.
- `escalation.md` — when something blocks you, who unblocks it.

Keep each file short: the trigger, the steps, the people (by role),
the source (who told you / which doc, and when).
